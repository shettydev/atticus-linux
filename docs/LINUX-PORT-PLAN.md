# Atticus Linux port plan

The reference implementation is Atticus 2.0.2 at commit `03260f7`. The first full-parity release targets **Ubuntu Desktop 26.04 LTS, GNOME on Wayland**. Build and test an amd64 Debian package on a stock Ubuntu installation with PipeWire and two displays. Record the Ubuntu point release, GNOME Shell, Mutter, portal backend and browser versions used for certification. All feature rows below apply to this release.

## First implementation

The Ubuntu packages now include the GTK/WebKitGTK typed ask box, a desktop launcher, a GNOME Shell shortcut and the verified `--place` command. Typed requests can launch an installed application or arrange a named open window. The two-monitor integration test builds and installs both packages, opens two GTK windows with similar titles, checks placement modes and rejects an ambiguous target. Run `./tests/gnome-smoke.sh` on a Docker host. Physical hardware, XWayland, mixed scaling, focusless overlays, voice, provider-backed asks and background work remain open in the parity matrix.

## Desktop and packaging decisions

- Ship an `atticus` .deb first. If the GNOME feasibility tests identify operations that need Shell access, offer a companion `gnome-shell-extension-atticus` .deb. Setup should show which features need it, help the user enable it in their session, and verify the bridge version and capabilities. Test installation from a local .deb with apt, extension enable/disable, compatible Shell updates and removal with user history retained.
- Start the Hyprland adapter after the GNOME vertical slice passes milestone 2. Keep it experimental during GNOME certification. Reuse the voice, accessibility, browser and agent code. Use Hyprland’s command and event IPC to prototype window identity, layout and workspace tracking. On a pinned Hyprland session, test placement in tiled and floating layouts, shortcut press/release, click-through drawings, covered-window previews and focus preservation while the user types. Record compositor and portal versions. Promote Hyprland to full support only when it passes the complete feature matrix. [Hyprland IPC](https://wiki.hypr.land/ipc/)
- KDE Plasma and standalone X11 are later candidates. Test XWayland applications inside the supported GNOME Wayland session from the first milestone.

## Architecture

Keep one product core. [atticus.py](../atticus.py) owns routing, provider clients, learning, command approval, agent lifecycle and much of the meeting archive. [ui/](../ui/) already contains the overlay, onboarding, settings, agents, meeting, math and browser page logic. [Atticus.swift](../Atticus.swift) is both a long-running GUI and a native helper executable. Python invokes that executable and also invokes AppleScript, Apple utilities and macOS applications directly. Changing the build target alone would leave both paths broken.

1. Keep the public Python CLI, helper exit codes, streamed output, JSON payloads, cancellation and existing on-disk formats. Introduce platform calls at their current boundaries, keeping the Darwin implementation callable throughout. Port the model's system prompt, tool examples, fast command generators, command classifiers and learned-command replay together. Test from an installed path with spaces. Mark stored Mac-specific shell recipes as needing re-learning on Linux. Preserve their original entries and portable user data.
2. Build a Linux session app in Python with PyGObject, GTK and WebKitGTK. Serve bundled assets locally and supply the same page-ready, message-handler and native-to-JavaScript contracts the pages use today. Put DBus, speech, capture and provider work off the UI thread. Retain one process responsible for panels, input state and the active turn. Have short-lived helper invocations address that process over a private per-user Unix socket with peer checks, request IDs, deadlines and explicit cancellation. Benchmark cold helper startup before moving hot paths into the daemon.
3. Define narrow desktop operations for shortcut edges, window identity/geometry, accessible actions, selected text, capture, audio, clipboard, notifications and scheduling. Return observed results and capability failures. Use AT-SPI2 for semantic app interaction and portals for consented capture and shortcuts. Prototype a versioned GNOME Shell extension for window placement, workspace identity and overlay behavior wherever testing shows the shared interfaces fall short. Give desktop bridges a fixed set of operations. Keep shell execution and provider credentials outside them. Exercise both native Wayland and XWayland apps through the GNOME adapter.
4. Give every action a stable target, an authorization decision and an observable result. A global input event goes to the active session and cannot serve as an implementation of background typing into a covered window. Prefer an app API, an accessible action on the identified element, or a browser tab owned by the task. A failed background action should produce the existing Needs you flow. Track the missing capability until it passes on that app and desktop.

## Verification and release

- Extend [check](../check) and [Ubuntu CI](../.github/workflows/checks.yml). Today Ubuntu runs host-safe regressions and skips Swift typechecking. Keep that fast lane, add Linux helper contract tests, and run the existing HTML fixtures through the real WebKitGTK bridge. Keep a Darwin regression lane for shared changes.
- Port behavior from the native fixtures, especially background send, owned edits, typing receipts, self-invisible capture, replay, meeting, whisper and platform preferences. Use disposable desktops for tests that manipulate focus or send input. Cover GTK, Qt, Electron/Chromium, terminal, office editor and an app with incomplete accessibility. Test on physical displays and audio devices before release.
- Run failure scenarios with a vanished target, ambiguous field, clipboard owner change, locked session, denied or revoked portal, missing model, signed-out provider, lost audio source, crashed compositor, worker restart, and upgrade of existing state. Confirm that retry observes what already occurred. Unsupported operations must have an actionable outcome and a visible status in the matrix.
- Carry over the [project budgets](GUIDE.md#budget): instant actions use zero AI, waiting costs zero, median AI ask below six seconds and $0.002 over the last 50, with existing prompt length limits. Measure speech finalization, hotkey-to-overlay latency, background CPU/RAM and continuous two-stream transcription on declared hardware. Publish the measured hardware and results.
- Suggested staffing: one desktop/compositor engineer, one Python/integrations engineer and shared QA on physical hardware. Milestones 0–1 are the first scheduling unit. Estimate remaining work per matrix row after those experiments. Background input, covered-window previews, browser profile integration and live speech are the critical path.

Technical reference for the shortcut prototype: the portal defines both activation and deactivation. Test key release, modifier-only bindings and registration conflicts on each backend. [Global Shortcuts interface](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.GlobalShortcuts.html)
